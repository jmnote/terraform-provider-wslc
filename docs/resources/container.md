# wslc_container (Resource)

Manages a WSL container's lifecycle via wslc.exe: `wslc create` followed by `wslc start`, and `wslc remove --force` on destroy. Every attribute besides `id` and `state` is immutable: wslc.exe has no in-place update for a container's image, command, environment, labels, or published ports, so changing any of them replaces the container.

~> **Destructive delete.** `terraform destroy`, or any change to an
attribute that forces replacement (every configurable attribute except
`id` and `state`), removes the container via `wslc remove --force`,
which **permanently deletes it and any data inside it that isn't in a
mounted volume**. There is no undo and this provider does not take
backups.

## Example Usage

```terraform
resource "wslc_container" "nginx" {
  name  = "example-nginx"
  image = "nginx:latest"
  pull  = "missing" # "always", "missing" (default), or "never"

  hostname = "nginx"
  cpus     = "1"
  memory   = "512M"

  env = {
    NGINX_ENTRYPOINT_QUIET_LOGS = "1"
  }

  labels = {
    "managed-by" = "terraform"
  }

  ports = [
    {
      host_port      = 18080
      container_port = 80
    }
  ]
}
```

## Schema

### Required

- `image` (String) The image to create the container from, e.g. "nginx:latest".
- `name` (String) The container's name, passed as `wslc create --name`.

### Optional

- `command` (List of String) Overrides the image's default command.
- `cpus` (String) CPU limit, e.g. "0.5", "1", "2.5", passed as `wslc create --cpus`.
- `dns` (List of String) DNS nameserver IPs written into the container's resolv.conf, passed as repeated `wslc create --dns`.
- `dns_options` (List of String) resolv.conf options (e.g. "ndots:5"), passed as repeated `wslc create --dns-option`.
- `dns_search` (List of String) DNS search domains, passed as repeated `wslc create --dns-search`.
- `domainname` (String) The container's domain name, passed as `wslc create --domainname`.
- `entrypoint` (String) Overrides the image's init process executable, passed as `wslc create --entrypoint`.
- `env` (Map of String) Environment variables set in the container, passed as repeated `wslc create --env`.
- `hostname` (String) The container's host name, passed as `wslc create --hostname`.
- `ip` (String) Static IPv4 address to assign the container on `network`, passed as `wslc create --ip`.
- `labels` (Map of String) Metadata set on the container, passed as repeated `wslc create --label`.
- `memory` (String) Memory limit, e.g. "512M", "1G", passed as `wslc create --memory`.
- `network` (String) Name of the network to connect the container to, passed as `wslc create --network`.
- `ports` (Attributes List) Ports to publish from the container to the host, passed as repeated `wslc create --publish`. (see [below for nested schema](#nestedatt--ports))
- `publish_all` (Boolean) Publishes every exposed port to a random host port, passed as `wslc create --publish-all`.
- `pull` (String) Image pull policy applied during creation: "always", "missing", or "never", passed as `wslc create --pull`. Defaults to wslc.exe's own default, "missing" (pull only if the image isn't already present locally).
- `rm` (Boolean) Removes the container once it stops, passed as `wslc create --rm`.
- `shm_size` (String) Size of /dev/shm, e.g. "64M", passed as `wslc create --shm-size`.
- `stop_signal` (String) Signal `wslc stop` sends by default, passed as `wslc create --stop-signal`.
- `stop_timeout` (Number) Seconds `wslc stop` waits by default before killing the container (-1 for no timeout), passed as `wslc create --stop-timeout`.
- `tmpfs` (List of String) tmpfs mounts (e.g. "/mytmp" or "/mytmp:size=100m"), passed as repeated `wslc create --tmpfs`.
- `ulimit` (List of String) Ulimit specs (format: "<name>=<soft>[:<hard>]", -1 for unlimited), passed as repeated `wslc create --ulimit`.
- `user` (String) User the process runs as (name|uid|uid:gid), passed as `wslc create --user`.
- `workdir` (String) Working directory inside the container, passed as `wslc create --workdir`.

### Read-Only

- `id` (String) The container's full ID, as assigned by wslc.exe. Also the `terraform import` identity.
- `state` (String) The container's current run status (e.g. "running", "exited"), as last observed from `wslc inspect`.

### Nested Schema for `ports`

Required:

- `container_port` (Number) Port inside the container to publish.
- `host_port` (Number) Port on the host to publish to.

## Import

Import uses the container's full ID as the import identity:

```shell
terraform import wslc_container.nginx <container-id>
```

`wslc inspect` reliably reports back `name`, `image`, and `state`, so
import populates those. Every other configurable attribute (`env`,
`cpus`, `dns`, `ports`, `labels`, etc.) cannot be read back from
wslc.exe and is left unset by import -- write matching values into your
configuration before the next `terraform plan`, or that plan will
propose replacing the container (since those attributes all force
replacement when they differ from state).

### Example

Assuming you created a container as follows

```shell
wslc create --name foo nginx:latest
# prints the container ID
9a550c0f0163d39d77222d3efd58701b625d47676c25c686c95b5b92d1cba6fd
```

you provide the definition for the resource as follows

```terraform
# Only name and image are included here, since those (along with the
# computed id/state) are the only attributes `terraform import` can
# populate from `wslc inspect`. Adding any other attribute (env, ports,
# cpus, etc.) after import forces a replace on the next apply, since
# there is nothing in state to compare it against -- see this resource's
# Import section above.
resource "wslc_container" "foo" {
  name  = "foo"
  image = "nginx:latest"
}
```

then the import command is as follows

```shell
terraform import wslc_container.foo 9a550c0f0163d39d77222d3efd58701b625d47676c25c686c95b5b92d1cba6fd
```
